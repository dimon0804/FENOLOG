# 🌾 Фенолог

**Мониторинг вегетационной динамики полей: восстановление рядов NDVI, поиск периодов
угнетения растительности и объяснение их причины человеческим языком.**

Решение кейса «Мониторинг вегетационной динамики» для Космохакатона.

---

## Что делает

Вы указываете поле на карте. Дальше сервис делает всё сам:

1. **Собирает данные.** Спутниковые снимки (Sentinel-2, Landsat, MODIS) и суточную
   метеосводку по контуру поля за всю доступную историю.
2. **Восстанавливает ряд.** Облака, разная периодичность пролётов и сбои съёмки
   оставляют в ряде NDVI дыры — от одного дня до полугода. Они заполняются.
3. **Сравнивает с нормой.** Для каждого дня года считается климатическая норма по
   собственной истории поля, а где истории нет — по типу культуры.
4. **Находит аномалии.** Периоды, когда растительность устойчиво ниже нормы,
   выделяются и классифицируются: штатное развитие, угнетение биомассы,
   критическая аномалия.
5. **Объясняет причину.** Не «аномалия обнаружена», а готовая фраза для агронома:

> «Осадков 41 мм при норме 62 мм (67 процентов), температура отличается от нормы
> на 0.1 градуса — ни засухи, ни жары, ни холода, ни переувлажнения за эти 45 дней
> не было. Погода отклонение не объясняет: проверяйте агротехнику, состояние семян,
> болезни и вредителей.»

## Результат

Метрика кейса — RMSE восстановления скрытых значений NDVI и производный от неё
`GapScore = 30 · max(0, 1 − RMSE / 0.1)`.

| Конфигурация | RMSE | GapScore |
| --- | ---: | ---: |
| Baseline организаторов (среднее двух соседей) | 0,0888 | 3,35 |
| Линейная интерполяция | 0,0880 | 3,60 |
| Сглаживание Уиттекера, λ = 1000 | 0,0794 | 6,17 |
| **Финальная конфигурация** | **0,0642** | **10,75** |

**Минус 27,7 % к baseline.** Результат проверен на трёх независимых разбиениях
(0,0642 / 0,0643 / 0,0666) — он не привязан к одному удачному контрольному набору.

## Главная идея решения

Считалось, что точность упирается в собственный шум наблюдения (~0,066) и ниже
RMSE 0,075 опуститься нельзя. **Это неверно.**

Шум наблюдения не независим между полями. Дымка, тонкое облако, угол Солнца и
поправки атмосферной коррекции сдвигают NDVI сразу у всех полей, снятых одним
пролётом спутника. А наблюдения **соседних** полей на дату пропуска доступны —
скрыто только целевое поле.

Значит общую суточную помеху можно измерить по соседям и вычесть.

![Суточная помеха](reports/figures/fig2_daily_correction.png)

Слева — один день: 50 полей из 55 промахиваются мимо своей сглаженной кривой в одну
и ту же сторону. Справа — что даёт снятие этой помехи на всех датах: разброс
остатка падает с 0,0643 до 0,0562, а при взвешивании соседей по корреляции — до
0,0518.

Один этот приём дал больше, чем все остальные вместе: **0,0794 → 0,0694**.

## Восстановление ряда

![Восстановление ряда NDVI](reports/figures/fig1_ndvi_restoration.png)

Финальная конфигурация — конвейер из четырёх шагов:

```
1. очистка ряда
     бракованные значения придавливаются к границе диапазона, а не выбрасываются
     мягкий медианный фильтр по календарному окну ±8 дней
     веса наблюдений по сенсору: Sentinel-2 / Landsat / MODIS = 1 / 0,8 / 0,5
2. суточная поправка по соседним полям
     вес соседа max(corr, 0,1)³ по корреляции остатков
3. сглаживание Уиттекера, λ = 500
4. на разрывах от 45 дней — климатологический якорь
     восстанавливается отклонение от нормы, а не сам NDVI
```

Выигрыш есть **во всех** диапазонах длины пропуска, а не только в среднем:

![RMSE по длине разрыва](reports/figures/fig4_rmse_by_gap.png)

## Поиск аномалий

Периоды угнетения выделяются по z-оценке отклонения от климатической нормы, близкие
периоды склеиваются, короткие выбросы отсеиваются. Версия причины выбирается по
погоде за тот же интервал.

![Разбор найденного случая](reports/figures/fig6_anomaly_case.png)

Согласие с эталонной разметкой (30 520 размеченных наблюдений):

| Показатель | Было | Стало |
| --- | ---: | ---: |
| Точность классификации | 0,916 | **0,938** |
| F1 «Угнетение биомассы» | 0,703 | **0,773** |
| F1 «Критическая аномалия» | 0,517 | **0,637** |
| Доля периодов, попадающих в разметку | 0,927 | **0,991** |

**Шесть версий причины:** дефицит влаги, температурный стресс, переувлажнение,
резкое одномоментное событие, затяжной холод и «причина не погодная» — последняя
не заглушка, а утверждение: все погодные пороги проверены и ни один не сработал.

## Как это проверялось

Лидерборд отдаёт одну цифру в сутки. Поэтому все решения принимались по локальной
валидации — и её корректность пришлось доказывать отдельно.

Наивное «спрятать 20 % случайных значений» не годится: у случайной точки пропуск
почти всегда короткий, а в реальном наборе встречаются разрывы до 189 дней, и
именно на них методы расходятся. Поэтому контрольные точки скрываются **по
шаблонам настоящих**: из данных снимается геометрия каждого реального пропуска
(расстояние до соседа слева, справа, месяц) и воспроизводится на известных
значениях.

![Совпадение геометрии](reports/figures/fig5_holdout_geometry.png)

Расхождение с реальным распределением — не больше 0,2 процентного пункта по любому
диапазону. Разбиение — GroupKFold по полям: поле целиком либо в обучении, либо в
контроле. У скрытых точек стираются **все** признаки, а не только целевой, — ровно
так замаскированы настоящие контрольные точки.

Это не формальность. **Первая версия протокола давала другое ранжирование методов**,
и решение, принятое по ней, увело бы всю работу не туда. Разбор — в отчёте.

## Как добавить свой метод восстановления

Методы лежат в реестре и подхватываются автоматически: новый метод — отдельный файл
`src/ml/m_*.py`, общие файлы править не нужно.

```python
from src.ml.registry import BaseMethod, register

@register("мой_метод", "Название для таблицы", experiment="E0X")
class МойМетод(BaseMethod):
    needs_fit = False   # True — метод обучается, тогда его прогонят через GroupKFold

    def predict(self, view, target_ords):
        ...  # -> np.ndarray той же длины, что target_ords
```

После этого `python -m src.ml.validate` сам включит его в сравнительную таблицу.

## Что не работает и где границы

Честный список — он же в отчёте подробнее.

- **Суточная поправка требует нескольких полей в одном регионе.** На единственном
  поле приём не работает вовсе, и результат откатывается к 0,0794. Это ограничение
  продукта, а не только метрики.
- **У полей без собственной истории норма берётся средняя по культуре.** Оценка
  ориентировочная, глубина отклонения может быть завышена или занижена. В ответе
  это видно в поле `meta["climatology_source"]`, интерфейс помечает такие поля.
- **Без метеоданных версия причины не определяется** — период всё равно находится,
  но объяснения не будет.
- **Побинный подбор параметров не переносится между разбиениями.** Проверяли,
  выигрыш держится только на своём наборе; в финальную конфигурацию не вошёл.
