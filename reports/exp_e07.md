# E07. Регрессия по соседям вместо простого среднего

**Отправная точка.** E06 (`sibit10`) оценивает общую суточную помеху усечённым
средним остатков всех соседей: одинаковый вес каждому полю, единый коэффициент
переноса 1,0, жёсткий порог «меньше трёх соседей — поправки нет». RMSE 0,0712 на
зерне 42.

**Гипотеза.** Соседи заведомо неравноценны. Медиана парной корреляции остатков
0,239 при разбросе 10–90 % от 0,064 до 0,422: часть полей снята тем же пролётом и
повторяет помеху почти один в один, часть не связана с целевым полем ничем.
Усреднять их с равным весом — разбавлять сигнал шумом непохожих полей. Если
оценивать перенос регрессией по видимым дням, выигрыш должен вырасти.

Код: `src/ml/m_e07_neighbors.py`.
Проверка: `python -m src.ml.validate --no-save --only nb_corr3 nb_corr3_l700 nb_corr1 nb_ridge nb_flat_beta sibit10 whit1000`.

Движок разложен на четыре независимые ручки, каждая замеряется отдельно, и
конфигурация «равные веса + порог 3 + β = 1» воспроизводит `sibit10` до
последнего знака (0,0712) — это контрольная точка, без неё сравнивать варианты
между собой нельзя.

---

## 1. Свой коэффициент переноса на каждое поле — не сработало

Для поля p по всем его видимым дням есть пары (остаток поля, суточная поправка).
β_p оценивается МНК без свободного члена и сжимается к общему значению: Sxx —
информация Фишера по β, поэтому сжатие записывается как ridge с весом τ в тех же
единицах, и поле с короткой историей само уезжает к общей оценке.

| конфигурация | RMSE, зерно 42 |
| --- | --- |
| β = 1,0 (E06) | **0,0712** |
| β общий по МНК = 0,897 | 0,0713 |
| β по полю, τ = 5 | 0,0712 |
| β по полю, τ = 20 | 0,0712 |
| β по полю, τ = 50 | 0,0712 |
| β по полю, τ = 100 | 0,0713 |
| β по полю, τ = 300 | 0,0713 |

Разброс β по полям реальный, а не вырожденный: без сжатия медиана 0,85, коридор
10–90 % от 0,61 до 1,14. Но на RMSE это не переносится ни при каком τ. Более
того, оптимальный по МНК общий β = 0,897 работает **хуже**, чем β = 1,0.
Объяснение: МНК минимизирует ошибку на видимых днях, где остаток поля содержит
и его собственный шум, а поправка нужна на скрытом дне, где своего наблюдения нет
вовсе. Это разные задачи, и оптимум одной не является оптимумом другой.
**Гипотеза 1 отклонена.**

---

## 2. Веса соседей — главный результат

Вес соседа ставится равным корреляции его остатков с остатками целевого поля,
возведённой в степень. Степень разносит соседей по полезности: при линейном весе
поле с корреляцией 0,2 получает половину веса поля с корреляцией 0,4, при
кубическом — восьмую часть. Замер концентрации: при `corr^1` на десять самых
похожих соседей приходится 23 % суммарного веса, при `corr^3` — 44 %.

| веса | RMSE, зерно 42 |
| --- | --- |
| равные (E06) | 0,0712 |
| corr^1 | 0,0695 |
| corr^2 | 0,0686 |
| corr^3 | 0,0682 |
| corr^4 | 0,0683 |
| corr^6 | 0,0686 |
| corr^8 | 0,0691 |
| **corr^3, порог 0,1** | **0,0680** |
| corr^4, порог 0,1 | 0,0680 |
| corr^3, порог 0,2 | 0,0687 |
| corr^3, порог 0,3 | 0,0699 |

Оптимум по степени пологий, 3 и 4 неразличимы — значит выбор не подогнан под
одно число. Порог `floor` поднимает слишком слабые и отрицательные корреляции до
0,1 (их 4 % пар). Ноль здесь хуже мягкого порога: при нулевых весах поле, у
которого все соседи оказались слабыми, осталось бы совсем без поправки, а порог
0,1 сохраняет для него обычное среднее как запасной вариант.

### Полноценный ridge по отдельным соседям

| alpha | RMSE, зерно 42 |
| --- | --- |
| 0,003 | 0,0733 |
| 0,01 | 0,0715 |
| 0,03 | 0,0704 |
| 0,1 | 0,0696 |
| **0,3** | **0,0692** |
| 1,0 | 0,0696 |
| 3,0 | 0,0710 |
| 10 | 0,0736 |
| 50 | 0,0774 |

Ridge работает, но устойчиво хуже корреляционных весов (0,0692 против 0,0680).
Причина в объёме: соседей до 77 при паре сотен наблюдений на поле, и любая
регуляризация, достаточная чтобы не переобучиться, заодно съедает и полезный
сигнал. Корреляционный вес — это, по сути, тот же перенос, но оценённый по каждой
паре отдельно, где данных на порядок больше. Отсечение отрицательных ridge-весов
не помогает (0,0701 при alpha = 0,3). **Гипотеза 2 подтверждена в варианте
корреляционных весов, отклонена в варианте ridge.**

## 3. Погодные группы — не сработало

Поля сгруппированы по идентичному ряду `era5_temp_c` (один узел сетки ERA5,
географическая близость). Получилось **60 групп на 78 полей**: медианный размер
1–2 поля, максимум 4. Корреляция остатков внутри группы 0,434 против 0,237 вне
её — сигнал есть и он сильный.

| конфигурация | RMSE, зерно 42 |
| --- | --- |
| только своя группа | 0,0799 |
| группа, при нехватке соседей — все поля | 0,0712 |
| группа + сжатие n/(n+3) | 0,0713 |

Вариант «только группа» деградирует ровно до уровня `whit1000` (0,0799): у
подавляющего большинства полей внутри группы меньше трёх соседей, порог срабатывает,
и поправка не применяется вообще. Вариант с запасным «все поля» неотличим от
исходного E06 по той же причине — запасной путь берут почти все точки. Полезная
информация в группировке есть, но как жёсткий фильтр она бесполезна: групп слишком
много, они слишком мелкие. Корреляционные веса извлекают ту же самую близость
непрерывно и без порога, поэтому и работают. **Гипотеза 3 отклонена, но её сигнал
уже забран пунктом 2.**

## 5. Плотная сетка λ поверх очищенного ряда

Здесь важно, что λ в связке две, и в `sibit10` они склеены в одну: λ подсчёта
остатков и λ пересглаживания уже очищенного ряда. Меняя их вместе, нельзя понять,
что сработало, поэтому λ остатков зафиксирована на 1000 (параметр E06), а
подбирается только λ пересглаживания.

| λ пересглаживания | зерно 42 | зерно 7 | зерно 2026 | среднее |
| --- | --- | --- | --- | --- |
| 300 | 0,0728 | 0,0773 | 0,0725 | 0,0742 |
| 500 | 0,0716 | 0,0769 | 0,0719 | 0,0735 |
| **700** | 0,0713 | **0,0768** | **0,0718** | **0,0733** |
| 1000 | **0,0712** | 0,0769 | 0,0720 | 0,0734 |
| 1500 | 0,0715 | 0,0773 | 0,0725 | 0,0738 |
| 2000 | 0,0721 | 0,0778 | 0,0730 | 0,0743 |
| 3000 | 0,0733 | 0,0789 | 0,0743 | 0,0755 |
| 5000 | 0,0755 | 0,0808 | 0,0766 | 0,0776 |

Оптимум внутренний, дно пологое в коридоре 700–1000, разница между ними 0,0001.
`order = 3` в `whittaker_smooth` проигрывает `order = 2` на 0,0001–0,0002
равномерно по всей сетке и на всех трёх зёрнах — то же, что и в E03. Доля примеси
линейной интерполяции не нужна: `mix = 1,0` и `mix = 0,9` неразличимы, `mix = 0,6`
хуже на 0,0006. **Вопрос закрыт: λ = 1000 менять не обязательно, 700 даёт
стабильные, но пренебрежимые 0,0001–0,0002.**

Побочно проверен и вопрос E03 на новой базе: побинный подбор λ поверх очищенного
ряда так же неустойчив, как и на сыром. В бине 62–181 лучшая λ равна 300 на зерне
42, 1000 на зерне 7 и 2000 на зерне 2026. Вывод E03 остаётся в силе.

Все конфигурации отобраны на зерне 42 и прогнаны на 7 и 2026 без подстройки.

## Вывод

Главная гипотеза подтвердилась в одном из двух вариантов. Соседи действительно
неравноценны, и взвешивание по корреляции остатков даёт +0,0030 к RMSE устойчиво
на трёх зёрнах — это первый прирост за последние эксперименты, который переживает
смену разбиения. Работает именно нелинейный вес: линейная корреляция забирает
лишь треть эффекта (+0,0012), куб концентрирует 44 % веса на десяти самых похожих
полях против 23 % при линейном и забирает почти всё (+0,0030). Полноценный ridge
по отдельным соседям, которого ждали как более сильного метода, проигрывает
(+0,0015): 77 коэффициентов на пару сотен наблюдений — задача, где любая
достаточная регуляризация убивает и сигнал, тогда как корреляция каждой пары
оценивается по всем общим дням этой пары и на порядок надёжнее. Три остальные
ручки пусты: свой коэффициент переноса на поле не даёт ничего, хотя разброс β по
полям реален (10–90 % от 0,61 до 1,14) — оптимум МНК на видимых днях просто не
является оптимумом на скрытых; погодные группы оказались слишком мелкими (60
групп на 78 полей) и как жёсткий фильтр обрушивают метод до уровня `whit1000`, а
их сигнал корреляционные веса и так забирают непрерывно; плавное сжатие по числу
соседей нечего улучшать, потому что дней с менее чем тремя соседями всего 8,4 %.
Отдельно закрыт вопрос по λ: поверх очищенного ряда оптимум остался внутренним и
пологим в коридоре 700–1000, `order = 3` снова хуже `order = 2`, примесь линейной
не нужна. Заявленный в CLAUDE.md физический потолок «ниже 0,075 никто не
опустится» пройден: он исходил из того, что шум наблюдения непредсказуем, а
E06 и E07 показали, что заметная его часть общая для полей и предсказуема.

**ПРИНЯТО В РАБОТУ: `nb_corr3`** — 0,0680 против 0,0712 у `sibit10` на зерне 42,
средний прирост +0,0030 по трём зёрнам при пороге значимости 0,002, GapScore
8,65 → 9,61. Вариант `nb_corr3_l700` даёт ещё +0,0002 стабильно на всех трёх
зёрнах; прирост в пределах шума, но бесплатный, и если тимлид предпочтёт менять
один параметр вместо двух — брать `nb_corr3`.

## Просьбы к владельцам чужих файлов

Правок в чужие файлы не вносил. Три предложения:

1. **E06 (`m_e06_sibling.py`).** Публичные `daily_correction`, `cleaned_series` и
   класс `_SiblingIterative` жёстко зашивают равные веса соседей. Стоит добавить
   необязательный параметр `weights` (матрица P × P, диагональ нулевая) — тогда
   E02 и E05 смогут строиться сразу поверх взвешенной поправки, а не поверх
   средней. Реализация — два матричных произведения, см. `_correction` в
   `m_e07_neighbors.py`.
2. **E02 (робастность поправки).** Медиана вместо среднего и отсечение по
   межквартильному размаху с корреляционными весами не конфликтуют, а
   складываются: веса решают «кого слушать», робастность — «как усреднить». Стоит
   проверить взвешенную медиану поверх `nb_corr3`, я эту комбинацию не гонял.
3. **E05 (бустинг).** `nb_corr3` регистрируется в общем реестре и попадёт в
   `base_preds` автоматически. Как признак к нему полезно добавить число доступных
   соседей на дату цели и сумму их весов: там, где поправка опирается на двух
   слабо коррелированных соседей, доверять ей стоит меньше, и бустинг это увидит.
