Каждая запись: гипотеза, что изменили, число до и после, вывод. Из этого журнала
собирается исследовательский отчёт — критерии «Baseline и отправная точка» и
«Эксперименты и сравнения», 10 баллов рубрики.

Числа по восстановлению пропусков (E00–E08) получены одной командой и сопоставимы
между собой:

```bash
python -m src.ml.validate
```

Записи E09–E13 относятся к слою автосбора данных и к доменному ядру, у них другие
контрольные наборы, и они названы у каждой записи отдельно: живое поле под Ростовом

оценки риска (E11), разметка `status` для починок ядра (E13). Числа из этих записей
с RMSE восстановления **не сопоставимы** и складывать их нельзя.

## Протокол локальной валидации

Лидерборд отдаёт одну цифру в сутки и годится только для проверки формата файла.
Все решения принимаются по локальному протоколу, и только по нему.

**Как строится контрольный набор.** Наивное «спрятать 20 % случайных известных
значений» не годится: у случайной точки разрыв почти всегда короткий, а в реальном
наборе организаторов встречаются разрывы до 189 дней, и именно на них методы
расходятся сильнее всего. Поэтому применяется маскирование по шаблону:

1. Из тестового файла снимается геометрия всех 3 112 контрольных точек — тройка
   «расстояние до ближайшего известного значения слева, расстояние справа, месяц».
2. Каждая такая тройка становится шаблоном. Чтобы его воспроизвести, берётся
   случайное известное наблюдение нужного месяца, и вместе с ним прячутся все
   наблюдения, попавшие внутрь интервала шаблона. Тогда у спрятанной точки соседи
   оказываются ровно там же, где у настоящей контрольной точки.
3. Размещение отбраковывается, если фактическая длина разрыва попала не в тот бин,
   что у шаблона. Без этой проверки захват соседей растягивает разрывы, локальный
   набор становится заметно тяжелее реального, и выводы смещаются: в первой версии
   протокола доля разрывов 14–29 дней вышла 37,6 % против реальных 15,9 %.
4. По бинам длины разрыва держится квота. Без неё короткие шаблоны, которым труднее
   найти место, недобираются, длинные добираются легко, и перекос возвращается.
5. У спрятанных строк стираются **все** признаки, кроме `anon_polygon_id`, `date` и
   `crop_type` — ровно так замаскированы настоящие контрольные точки. Иначе
   валидация мерила бы задачу легче реальной.
6. Оценивается только центр шаблона. Соседи, снесённые заодно, из обучения выбывают,
   но в метрику не идут — иначе набор перекосило бы в сторону коротких разрывов.
7. Центром шаблона может быть только строка тестового файла: именно такие строки
   мы предсказываем на самом деле.

**Результат — совпадение геометрии по всем бинам:**

| разрыв, дней | контрольные точки, % | локальная валидация, % |
| --- | --- | --- |
| 1–2 | 6,6 | 6,5 |
| 3–4 | 17,7 | 17,8 |
| 5–7 | 27,3 | 27,4 |
| 8–13 | 27,5 | 27,6 |
| 14–29 | 15,8 | 15,6 |
| 30–61 | 1,4 | 1,4 |
| 62–181 | 3,2 | 3,2 |
| 182+ | 0,4 | 0,4 |

**Разбиение.** GroupKFold по `anon_polygon_id`, 5 фолдов: поле целиком либо в
обучении, либо в контроле. Иначе бустинг подглядит соседние дни того же поля и
локальная цифра разойдётся с лидербордом.

**Объём.** 2 999 оцениваемых точек, 8 094 скрытых строки (16,8 % известных
значений), 78 полигонов, зерно 42. Протокол детерминирован.

**Метрика.** `RMSE` по спрятанным точкам и `GapScore = round(30 · max(0, 1 − RMSE / 0.10), 2)`.

**Что исключено сознательно.** Шаблоны с односторонним разрывом (край ряда)
отброшены: воспроизвести их, не разрушив полигон целиком, нельзя. В реальном
наборе таких точек меньше процента.

## E00. Разведка данных

**Что делали.** Разбор `private_features.csv`, затем — после появления —
`train_dataset.csv`. Подробности во втором файле: `reports/eda_train.md`.

**Наблюдения по тестовому набору.**

1. `primary_ndvi` — склейка трёх сенсоров по приоритету. Там, где доступен
   Sentinel-2, значение совпадает с `s2_ndvi` до последнего знака: проверено на
   7 815 строках, доля точных совпадений 1,000. Иначе Landsat, иначе MODIS.
2. В контрольных строках замаскированы все признаки, кроме `anon_polygon_id`,
   `date` и `crop_type`. Даже `doy`, `year`, погода и климатология.
3. Разрывы короткие: медиана расстояния до ближайшего известного значения — 3 дня
   с каждой стороны, 75-й процентиль 6 дней, максимум 189. У 99,2 % контрольных
   точек соседи есть с обеих сторон, экстраполяция почти не нужна.
4. История неравномерна: 19 полигонов покрывают 2010–2025, остальные 59 — только
   сезон 2025. Климатическая норма по собственной истории доступна не всем.

**Наблюдения по обучающему набору (99 955 строк, 39 полигонов).**

5. **Сплит между файлами идёт по годам, а не по датам.** Пересечение пар
   «полигон + дата» ровно нулевое, и пересечение пар «полигон + год» тоже ровно
   нулевое: для всех 39 полигонов train — это сезоны 2010–2024, а test — только
   сезон 2025. Ближайшее наблюдение train к контрольной точке отстоит минимум на
   153 дня. Отсюда прямое следствие, проверенное числом в E01b.
6. **Формула климатологии восстановлена точно.** `ndvi_climatology_mean` — это
   среднее `primary_ndvi` того же полигона по всем годам **кроме текущего**, в окне
   ±8 дней по дню года. MAE воспроизведения 0,00163; окна ±7 и ±9 дают 0,006 и
   0,005, то есть ширина определена однозначно. `n_reference_years = 15` при 16
   годах истории — это leave-one-out. Следствие: замаскированную у контрольных
   точек климатологию можно пересчитать самостоятельно и получить её для 2 884 из
   3 112 точек (92,7 %).
7. **`ndvi_zscore` = (primary_ndvi − clim_mean) / clim_std**, 30 520 из 30 520
   точных совпадений, максимальное расхождение 3,2·10⁻¹⁴. Сглаживания нет.
8. **Разметка `status` воспроизводится порогами из `src/contracts.py` идеально:**
   z ≥ −1 «Штатное развитие», −2 ≤ z < −1 «Угнетение биомассы», z < −2
   «Критическая аномалия». Совпадение 1,000000, ошибок 0 из 30 520.
9. **Собственный шум наблюдения 0,066.** std разности значений при шаге ровно один
   день равен 0,0931, отсюда шум одного наблюдения 0,0931/√2.
10. **Одиночные выбросы измерены:** 5,60 % троек подряд идущих наблюдений, где
    средняя точка отклоняется от полусуммы соседей больше чем на 0,10 при
    расхождении самих соседей меньше 0,05. При пороге 0,15 — 3,15 %. Значений вне
    диапазона [0, 1] в train 38, все отрицательные.
11. **Погода частично восстановима.** `era5_temp_c` принимает 9–12 уникальных
    значений на дату при 78 полигонах: поля сбиваются в 37 погодных групп с общей
    метеосводкой. 782 контрольные точки (25,1 %) получают точную погоду от
    полигона-собрата из той же группы на ту же дату.
12. **Норма по типу культуры как предиктор слаба.** Медиана корреляции кривых
    внутри культуры 0,949 против 0,855 между культурами; RMSE между двумя полями
    озимой пшеницы 0,108 — хуже текущей ошибки восстановления.

**Вывод.** Основной источник ошибки — не разрывы, а шум наблюдения: 0,066 против
рабочих 0,080 RMSE. Значит рычаг не в точности интерполяции между двумя точками, а
в подавлении шума по окну, и запас до физического потолка невелик.

## E02. Робастная очистка ряда

**Гипотеза.** Собственный шум наблюдения 0,066 — основной источник ошибки. Кроме
грубого брака (значения вне [0, 1]) есть одиночные провалы от облачности: сенсор
занижает NDVI на одну дату, соседние даты нормальные. Сглаживание такой провал
размазывает по окрестности вместо того, чтобы его выкинуть. Медианный фильтр по
трём точкам перед сглаживанием должен дать выигрыш.

**Что изменили.** Проверено 47 вариантов конвейера «очистка → сглаживание».

| Компонент, накопительно | RMSE | Дельта |
| --- | --- | --- |
| Контроль (Уиттекер λ = 1000) | 0,0799 | — |
| Веса наблюдений по сенсору 1 / 0,8 / 0,5, λ = 800 | 0,0786 | −0,0013 |
| + придавливание брака к границе вместо выбрасывания | 0,0781 | −0,0018 |
| + мягкая медиана по трём точкам, порог 0,20 | 0,0777 | −0,0022 |
| + окно медианы по календарю ±8 дней вместо трёх подряд идущих наблюдений | **0,0765** | **−0,0034** |

**Три находки, которые стоят отдельного упоминания.**

1. **Гипотеза про асимметрию опровергнута.** Считалось, что облачность занижает
   NDVI, но почти никогда не завышает. На данных наоборот: одиночных всплесков
   вверх больше, чем провалов вниз — 41–44 % вниз на всех порогах, и на train, и
   на test. Зеркальный фильтр «сбивать только всплески вверх» (0,0795) обгоняет
   фильтр «сбивать только провалы вниз» (0,0801). Асимметрия есть только в дальнем
   хвосте и в грубом браке.
2. **Выбрасывать бракованную точку хуже, чем оставить.** Придавливание к границе
   даёт −0,0005, и весь эффект сидит в бине 62–181 дня (0,1341 → 0,1215). Это края
   сезона, где выброшенная точка была единственной опорой перед зимним перерывом.
3. **Календарное окно решает больше, чем сам фильтр.** По отдельности мягкая
   медиана давала −0,0008, календарный режим не давал ничего, а в сборке разница
   между режимами составила 0,0012 — больше, чем каждый компонент поодиночке.

**Веса по сенсору прошли два контроля,** и это важно, потому что эффект от них
самый крупный. Первый: подбор λ без весов ничего не даёт (λ = 1250 → 0,0799,
λ = 2000 → 0,0803), то есть выигрыш не сводится к смещению силы сглаживания.
Второй: те же веса, розданные наблюдениям случайно, дают 0,0804 — хуже контроля.
Измеренный шум: Sentinel-2 0,0394, Landsat 0,0536.

**Честная оговорка про величину.** Окно и порог подбирались на зерне 42. Порядок
методов на других зёрнах сохраняется и лучший вариант ни разу не проигрывает, но
выигрыш меньше: −0,0034 на зерне 42, −0,0014 на 7, −0,0009 на 2024. Реалистичная
оценка эффекта — **около двух тысячных**, а не три с половиной.

**Принято в работу.** Конвейер `e02_wsoft_clamp_s20t`. Пересечение с E06 меряется
отдельно — оба метода сильнее всего играют на длинных разрывах, складывать их
эффекты нельзя.

## E03. Сила сглаживания под длину разрыва

**Гипотеза.** Единая λ на весь ряд — компромисс. На коротком разрыве сглаживание
должно быть слабее, чтобы не срезать реальную динамику; на длинном сильнее.

**Что изменили.** Сетка единой λ от 300 до 50 000 на трёх зёрнах; `order = 3`
вместо 2; побинный подбор λ и доли примеси линейной интерполяции.

| Проверка | λ = 1000 | Побинный подбор | Дельта |
| --- | --- | --- | --- |
| Конфигурация подобрана на зерне 42, проверка на зерне 42 | 0,0799 | 0,0793 | +0,0006 |
| Та же конфигурация, проверка на зерне 7 | 0,0854 | 0,0856 | −0,0001 |
| Та же конфигурация, проверка на зерне 2026 | 0,0808 | 0,0809 | −0,0001 |

**Вывод. Гипотеза не подтвердилась.** Выигрыш держится только на том наборе, на
котором подбирался, и не переносится. Сам выбор λ пляшет от зерна: для бина
62–181 дня оптимум оказывается λ = 50 000 при доле линейной 0,8 на зерне 42,
λ = 2000 при доле 0,4 на зерне 7 и λ = 3000 при чистом Уиттекере на зерне 2026.
Причина простая — объём: в бинах 30–61 и 62–181 всего 43 и 96 точек.

Побочные результаты, которые закрывают вопросы окончательно:

- Оптимум единой λ = 1000 подтверждён на трёх зёрнах и он внутренний, не на
  границе сетки; дно пологое, λ от 700 до 1500 различаются на 0,0002.
- `order = 3` равномерно хуже на 0,0002–0,0004 по всей сетке и на всех зёрнах.
- Примесь линейной интерполяции при правильной λ не нужна вовсе. Смесь 50/50 из
  E01 выигрывала только потому, что компенсировала недосглаживание при λ = 100.

**ОТКЛОНЕНО: прирост в пределах шума.** Методы оставлены в реестре как
воспроизводимое подтверждение замера, в финальную конфигурацию не идут.

## E06. Суточная поправка по соседним полям

Эксперимента не было в исходном плане. Он дал самый крупный прирост в проекте.

**Гипотеза.** Считалось, что 0,066 собственного шума наблюдения — неустранимый
потолок, потому что шум независим. Это неверно. Значительная его часть общая для
полей, снятых одним пролётом: дымка, тонкое облако, угол Солнца, поправки
атмосферной коррекции сдвигают NDVI сразу у группы полигонов в одну сторону. А
наблюдения соседних полей на дату контрольной точки **не замаскированы** —
организаторы прячут только целевой полигон.

**Проверка гипотезы до написания метода.**

| Величина | Значение |
| --- | --- |
| Стандартное отклонение остатка от сглаженного ряда | 0,0643 |
| Медиана парной корреляции остатков, все пары полигонов | 0,246 |
| Медиана корреляции остатка поля со средним остатком его погодной группы | 0,521 |

Погодные группы определяются по `era5_temp_c`: она принимает 9–12 уникальных
значений на дату при 78 полигонах, то есть поля сбиваются примерно в 37 групп с
общей метеосводкой. Корреляция 0,52 означает, что около четверти дисперсии
«шума» объяснимо и его можно вычесть.

**Что изменили.** Две версии.

Простая — восстановить ряд как обычно, затем прибавить долю от агрегата остатков
соседей на дату цели. Усиленная — та же суточная помеха сидит и в опорных
наблюдениях самого поля, значит её надо сначала вычесть из всего ряда,
пересгладить очищенные значения, и только потом вернуть на дате цели:

```
c(t)  — общая суточная поправка, усечённое среднее остатков по всем полям
y'(d) = y(d) − c(d)                     очищенные наблюдения
прогноз = сглаженный y'(t) + beta · c(t)
```

Поправка для каждого поля считается **без него самого** (leave-one-out), иначе
поле частично вычитало бы собственный шум и оценка была бы смещённой.

| Вариант | RMSE | GapScore |
| --- | --- | --- |
| Уиттекер λ = 1000 (контроль) | 0,0799 | 6,02 |
| Тот же метод при beta = 0 — проверка реализации | 0,0799 | 6,02 |
| Остаток соседей, доля 0,3 | 0,0768 | 6,96 |
| Остаток соседей, доля 0,5 | 0,0753 | 7,42 |
| Остаток соседей, доля 0,7 | 0,0742 | 7,73 |
| Остаток соседей, доля 1,0 | 0,0735 | 7,96 |
| Остаток соседей, доля 1,2 | 0,0738 | 7,86 |
| Суточная поправка до сглаживания, доля 0,8 | 0,0714 | 8,59 |
| **Суточная поправка до сглаживания, доля 1,0** | **0,0712** | **8,65** |

Контроль при beta = 0 совпадает с базовым методом до последнего знака — значит
выигрыш даёт именно поправка, а не побочные изменения в механике.

**Разрез по длине разрыва, RMSE:**

| Метод | 1–2 | 3–4 | 5–7 | 8–13 | 14–29 | 30–61 | 62–181 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Уиттекер λ = 1000 | 0,0588 | 0,0719 | 0,0795 | 0,0770 | 0,0841 | 0,0969 | 0,1341 |
| Остаток соседей, доля 1,0 | 0,0514 | 0,0671 | 0,0741 | 0,0683 | 0,0775 | 0,0843 | 0,1288 |
| Суточная поправка, доля 1,0 | 0,0521 | 0,0662 | 0,0730 | 0,0659 | 0,0756 | 0,0819 | **0,1129** |

Выигрыш во всех бинах без исключения, максимальный — на самых длинных разрывах.

**Устойчивость.** Оптимум по доле переноса пологий: 0,9 и 1,0 дают 0,0735, 1,2
даёт 0,0738 — это не остриё. Проверка на другом зерне: база 0,0854, метод 0,0769,
прирост 0,0085 против 0,0087 на зерне 42. λ = 1000 выигрывает на обоих зёрнах
(λ = 300 → 0,0731, λ = 3000 → 0,0729 при зерне 42).

**Величина эффекта.** Стандартное отклонение самой суточной поправки 0,0339 при
разбросе остатка 0,0643, поправка применяется на 95 % дней. То есть из шума
наблюдения снимается около половины по амплитуде.

**Вывод.** Утверждение «ниже RMSE 0,075 не опустится никто» опирается на
предположение, что шум наблюдения независим между полями. Предположение неверное.
Физический потолок надо пересчитывать по остаточному шуму после снятия общей
составляющей: 0,0643 → около 0,055.

**Принято в работу.** `sibit10` — новая точка отсчёта вместо `whit1000`.
Механика вынесена в публичные функции `daily_correction`, `cleaned_series`,
`correction_at`, чтобы остальные эксперименты строились поверх очищенного ряда.

## Исправление протокола: расстояния до соседей

Ошибку нашёл эксперимент E04, и она стоила бы дорого, если бы всплыла позже.

**Что было не так.** Расстояния `left_dist` и `right_dist` записывались в момент
размещения шаблона и дальше не обновлялись. Более поздний шаблон мог спрятать
наблюдение, которое раньше было засчитано соседом уже собранной точки, — и тогда
реальный разрыв оказывался длиннее записанного. Расходились 4,4 % точек, в
отдельных случаях катастрофически: у `AOI-0013` записан разрыв 4 дня при
фактических 168.

**Чем это грозило.** Сама RMSE не искажалась: методы предсказывают по данным, а не
по записанным расстояниям. Но портился разрез по бинам длины разрыва — то есть
именно та таблица, по которой принимались решения в E03 и E04. И портились
признаки «расстояние до соседа» у бустинга: часть строк обучающей выборки была
просто неверна.

**Как исправлено.** Соседи уже собранной контрольной точки помечаются защищёнными,
и размещение, которое захватило бы защищённое наблюдение, отбраковывается целиком.
Плюс контрольный пересчёт расстояний по факту после сборки набора — он теперь
должен быть тождественным, и это проверка на будущее.

**Что изменилось в числах.** Контрольный набор стал чуть легче, потому что разрывы
больше не растягиваются задним числом. Все выводы устояли, приросты даже выросли.

**Опорные методы перемеряны заново, все на исправленном протоколе:**

| Метод | зерно 42 | зерно 7 | зерно 2026 | было (черновой протокол) |
| --- | --- | --- | --- | --- |
| Среднее двух соседей (baseline организаторов) | 0,0888 | 0,0875 | 0,0919 | 0,0915 |
| Линейная интерполяция | 0,0880 | 0,0863 | 0,0897 | 0,0886 |
| Смесь λ = 100 и линейной 50/50 | 0,0834 | 0,0824 | 0,0848 | 0,0858 |
| Уиттекер λ = 1000 | 0,0794 | 0,0776 | 0,0796 | 0,0799 |
| Суточная поправка (E06) | 0,0694 | — | — | 0,0712 |

**Важно для отчёта и защиты.** Числа экспериментов E01–E07 в разделах выше сняты
до этого исправления, а E08 и итоговые — после. Складывать их между собой нельзя.
Единственная сопоставимая пара «baseline против финала» — та, что перемеряна здесь:
**0,0888 → 0,0642 на зерне 42**, то есть 27,7 %, а не 30 %, как получалось при
сравнении с доисправленным baseline. Разница невелика, но заявлять надо честную.

## E04. Климатологический якорь

**Гипотеза.** На длинном разрыве интерполяция тянет прямую через сезонный подъём
или спад NDVI и грубо ошибается: за 189 дней культура успевает пройти весь цикл.
Если интерполировать отклонение от климатической нормы, форма сезонной кривой
восстановится из нормы, а интерполяция будет отвечать только за медленный остаток.

**Гипотеза проверена до всякого RMSE.** Остаток от нормы действительно глаже:
стандартное отклонение приращения на лаге 62–181 день 0,247 против 0,283 у самого
NDVI. На лагах до недели выигрыша нет вовсе. Это сразу предсказало и то, что нужен
порог включения, и то, что остаток надо сглаживать сильнее.

**Что изменили.** Прямая схема «вычесть норму → восстановить → прибавить» даёт
**хуже** базы (0,0733 против 0,0712 на старом протоколе). Понадобились три поправки:

1. **У остатка свой оптимум сглаживания** — λ = 100 000 против 1 000 у сырого NDVI.
   Остаток это медленная аномалия сезона, у него нет быстрой динамики, которую λ
   обязан пропускать.
2. **Порог включения 45 дней.** На разрывах короче двух недель якорь только
   добавляет собственную ошибку нормы.
3. **Половинная доля якоря в смеси.** Оптимальный вес, посчитанный независимо на
   трёх зёрнах и четырёх источниках нормы, устойчиво лежит в диапазоне 0,33–0,58.
   Полная замена базы якорем на зерне 7 проигрывала, половинная выигрывает на всех
   трёх зёрнах.

| Вариант | RMSE | GapScore |
| --- | --- | --- |
| База (суточная поправка) | 0,0712 | 8,65 |
| Прямая схема «вычесть норму — восстановить — прибавить» | 0,0733 | 8,01 |
| **Якорь с порогом 45 дней и половинной долей** | **0,0702** | **8,93** |

На разрывах от 62 дней: 0,1129 → 0,1044 на зерне 42, а усреднённо по трём зёрнам
0,1013 → 0,0898, то есть минус 11 %. Общая RMSE двигается меньше, потому что
длинные разрывы — это 5 % точек.

**Побочные результаты, каждый из которых закрывает отдельный вопрос.**

- **Три схемы усреднения кривых культуры**, проверка leave-one-polygon-out по 58
  полям: сырое усреднение 0,0955, с вычитанием собственного среднего 0,0955,
  с делением на размах 0,0968; для сравнения «нормы нет вовсе» 0,1817. Первые две
  совпадают тождественно — центрирование сдвигает среднюю кривую на константу, а в
  якоре константа сокращается. Деление на размах вредит.
- **Два пути к норме.** Лучше работает готовая колонка `ndvi_climatology_mean`,
  свёрнутая по дню года (покрытие 99,9 %), чем пересчёт по восстановленной формуле
  организаторов (91,2 %): норма с исключением текущего года своя на каждый сезон и
  потому извилистее. Для z-оценки в доменном ядре вывод обратный — там нужен
  именно пересчёт, потому что там важна честность, а не гладкость.
- **Норма по типу культуры как предиктор бесполезна** (RMSE 0,166 против 0,071 у
  восстановления) — разведка подтверждена. Но внутри якоря она работает почти
  наравне со своей нормой, потому что якорю нужна только форма кривой, а не
  уровень. Отдельный метод «якорь по культуре для полей без истории» даёт ровно
  ноль: длинных разрывов у таких полей нет.

**Принято в работу.** `e04_anchor`. Отдельная рекомендация для бустинга: якорь
лучше отдавать признаком, а не готовым ответом — раз оптимальный вес плавает от
0,33 до 0,58, модель, знающая длину разрыва и разброс нормы, выберет его точнее
любой константы.

## E06b. Вес соседа по корреляции остатков

Продолжение E06, приём найден при разборе робастных статистик в E02.

**Гипотеза.** В E06 все соседи имеют равный вес. Но сосед, который исторически
ошибается вместе с нами, несёт про нашу ошибку больше информации, чем поле за сто
километров. Вес соседа должен зависеть от корреляции его остатков с нашими.

**Что изменили.** Вместо усечённого среднего — взвешенное, с весом
`max(corr, 0) ** 3`, где `corr` считается по всей таблице остатков. Диагональ
матрицы весов обнуляется — это и есть leave-one-out, поле не участвует в
собственной поправке. Реализовано двумя матричными умножениями, стоимость около
секунды на прогон.

| Вариант | RMSE | GapScore |
| --- | --- | --- |
| Равные веса (E06) | 0,0694 | 9,19 |
| Вес corr², λ = 500 | 0,0669 | 9,93 |
| **Вес corr³** | **0,0664** | **10,08** |
| Вес corr³, λ = 500 | 0,0665 | 10,06 |
| Вес corr⁴, λ = 500 | 0,0664 | 10,08 |

Оптимум степени 3, плато от 2 до 4 — не остриё. **Плавное взвешивание обгоняет
отбор top-k соседей при любом k:** слабые соседи не мусор, их вклад просто должен
быть меньше.

**Что при этом не сработало, и это важно.**

- **Робастные статистики после взвешивания вредят.** Медиана остатков вместо
  среднего даёт +0,0009, отбраковка по межквартильному размаху +0,0003. Подрезка
  ±0,25 уже сняла всё, что снималось робастной статистикой.
- **Вес соседа по шуму его сенсора не даёт ничего** (+0,0002), а в связке с
  корреляционным весом даже вредит: корреляционный вес уже неявно содержит
  информацию о качестве сенсора, и получается двойной счёт.
- **Асимметрия подрезки подтвердилась, но пользы не дала.** Распределение остатков
  скошено влево (асимметрия −1,23; за пределами ±0,35 сорок шесть провалов против
  шести всплесков) — облачность занижает NDVI сильнее, чем что-либо его завышает.
  Но асимметричная подрезка [−0,15; +0,25] даёт 0,0656 против 0,0657 у
  симметричной. После корреляционных весов способ подрезки перестаёт значить
  вообще: восемь вариантов от ±0,10 до ±0,50 укладываются в 0,0005.

**Принято в работу.** `sibw3` — новая база вместо `sibit10`. Приём внесён в
`daily_correction` и `cleaned_series`, то есть все методы, которые строятся поверх
очищенного ряда, получают его автоматически.


## E05. LightGBM поверх остальных методов

**Гипотеза.** Ни один метод не лучший везде: на коротких разрывах выигрывает слабое
сглаживание, на длинных — климатологический якорь. Бустинг, которому на вход дали
предсказания всех методов плюс контекст точки, должен научиться взвешивать их под
ситуацию и обогнать любого по отдельности.

**Что изменили.** 222 признака: предсказания всех 140 методов без обучения, их
разброс между собой, расстояния до соседей и производные, число наблюдений в окнах
±7/±15/±30/±60 дней, климатическая норма и её разброс, отклонение соседей от нормы,
тип культуры, гармоники дня года, погода из соседних дат и из полей той же погодной
группы, величина суточной поправки и число сформировавших её соседей. Целевая —
само значение, функция потерь MSE: она совпадает с оцениваемой метрикой.

| Конфигурация | RMSE |
| --- | --- |
| Простое среднее всех 140 методов | 0,0689 |
| `final` — лучший метод без обучения | 0,0642 |
| Бустинг, только контекст, **без предсказаний методов** | 0,0635 |
| Бустинг, только предсказания методов | 0,0616 |
| Бустинг, все признаки, без расширения выборки | 0,0616 |
| **`e05_lgbm` — все признаки, +5 реплик train** | **0,0596** |

**Проверка переноса между зёрнами — условие приёмки.** Конфигурация зафиксирована
на зерне 42 и на чужих зёрнах не перебиралась; модель обучается заново на своём
контрольном наборе.

| Зерно | `final` | `e05_lgbm` | Дельта |
| --- | --- | --- | --- |
| 42 | 0,0642 | 0,0596 | −0,0046 |
| 7 | 0,0643 | 0,0597 | −0,0046 |
| 2026 | 0,0666 | 0,0638 | −0,0028 |

Знак не меняется ни разу. Зерно 2026 даёт объективно более тяжёлый набор, там
выигрыш сжимается, но остаётся уверенно положительным. На зерне 7 выигрыш во всех
семи бинах длины разрыва; на 2026 проигрышный бин один — 30–61 день, где всего
43 точки из 2999, и разница на таком объёме от нуля неотличима.

**Аудит утечки — отдельно и числом.** 39 полигонов есть и в тесте, и в обучающем
наборе. Реплика, построенная по полю из train, не должна попасть в обучение к
контрольной точке того же поля из теста: иначе поле оказалось бы по обе стороны
разреза, просто в разные годы.

| Зерно | Доп. строк в обучении по фолдам | Из них с полигонов контроля | Было доступно на этих полигонах |
| --- | --- | --- | --- |
| 7 | 10 877 / 13 861 / 14 274 / 13 153 / 12 943 | **0 / 0 / 0 / 0 / 0** | 5400 / 2416 / 2003 / 3124 / 3334 |
| 2026 | 13 660 / 10 718 / 13 355 / 14 179 / 13 100 | **0 / 0 / 0 / 0 / 0** | 2593 / 5535 / 2898 / 2074 / 3153 |

Фильтр работает не вхолостую: на полигонах контрольного фолда лежало от двух до
пяти с половиной тысяч строк реплик, и все отброшены. Три остальных канала закрыты
по построению: реплики строятся поверх уже замаскированной таблицы, базовые
предсказания для них считаются по представлениям из неё же, а погодные группы
читают только метеоколонки и собственную колонку полигона в выдачу не включают.

**Главный рычаг — не гиперпараметры, а объём выборки.** Пары «полигон + дата» между
файлами не пересекаются, поэтому поверх строк `train_dataset.csv` строится второй,
независимый контрольный набор теми же шаблонами разрывов. Пять розыгрышей дают
+16 250 обучающих точек и **−0,0020**, тогда как весь перебор гиперпараметров —
−0,0006. Кривая выходит на полку к пятой реплике.

**Что показала важность признаков, и почему по ней нельзя судить прямо.** 95,5 %
вклада по gain приходится на предсказания методов, и лидируют очищенные ряды E02b с
разной λ — модель фактически подбирает силу сглаживания под конкретную точку.
Контекст даёт всего 4,5 % gain, но при этом стоит −0,0019 в метрике: модель,
которая видит **только** контекст и вообще не видит предсказаний, даёт 0,0635 и уже
обгоняет `final`. Из контекстных признаков первыми идут не значения, а **меры
неопределённости**: разброс остатков соседей, их число, корреляционный вес,
изменчивость наблюдений в окне. Погода — единственный блок с эффектом около нуля.

**Прямая цель против поправки к опоре.** Обучение на `truth − final` даёт то же
0,0596, на `truth − sibit10` хуже (0,0603). Оставлена прямая постановка: она не
привязана к чужому ключу в реестре и переживёт замену опорного метода.

**Цена.** Обучение с нуля на холодном кэше около 11 минут, из них 8 — прогон всех
базовых методов по пяти репликам. На тёплом кэше 165 секунд. Обученная модель
лежит в `models/e05_lgbm.pkl` и поднимается без обучения.

**ПРИНЯТО В РАБОТУ:** `e05_lgbm`. Новая финальная конфигурация проекта.

## E07. Регрессия по соседям вместо простого среднего

**Гипотеза.** В E06b соседи взвешиваются корреляцией, но доля переноса — одна
константа на все 78 полей, а порог по числу соседей жёсткий. Регрессия должна
оценить и то, и другое точнее.

**Что изменили.** Четыре независимые гипотезы, каждая поверх `corr³`, каждая на
трёх зёрнах.

| Гипотеза | Средняя дельта | Вердикт |
| --- | --- | --- |
| Своя доля переноса на каждое поле со сжатием к общей | −0,0000 | отклонена |
| Плавное сжатие по числу соседей вместо порога | +0,0002 | отклонена |
| Ridge по остаткам отдельных соседей | −0,0008 | отклонена, проигрывает corr³ |
| Погодные группы как фильтр соседей | +0,0001 | отклонена |
| Плотная сетка λ | — | подтверждено: оптимум 500–600, плато 400–800 |

**ОТКЛОНЕНО.** Итог `nb_corr3_sh` 0,0655 / 0,0650 / 0,0680 против `e02s_best`
0,0655 / 0,0647 / 0,0676 — не обгоняет базу ни на одном зерне.

**Почему не сработало — это содержательнее самих цифр.**

- **Своя доля переноса.** Разброс по полям реален (между десятым и девяностым
  процентилями от 0,60 до 1,13), но метод наименьших квадратов минимизирует
  ошибку на видимых днях, где у поля есть собственное наблюдение. Поправка же
  нужна на скрытом дне, где его нет. Подогнанная доля 0,896 не обгоняет наивную
  единицу.
- **Плавное сжатие по числу соседей.** Дней, где соседей меньше трёх, всего
  8,6 % — крутить попросту нечего.
- **Ridge.** Семьдесят семь коэффициентов на пару сотен наблюдений. Регуляризация,
  достаточная против переобучения, убивает вместе с шумом и сигнал. Корреляция
  пары оценивается по всем общим дням этой пары, то есть данных на порядок
  больше. Смесь corr³ и ridge даёт +0,0001 — ridge не содержит ничего сверх
  корреляции.
- **Погодные группы.** Сигнал несомненный: корреляция остатков внутри группы
  0,441 против 0,230 вне. Но групп 60 на 78 полей, из них 49 одиночек. Как жёсткий
  фильтр приём обрушивает метод до уровня Уиттекера без поправки (0,0794).
  Корреляционные веса извлекают ту же географическую близость непрерывно и
  полностью, поэтому явное деление на группы уже ничего не добавляет.

**Одна находка забрана в работу.** Нижний порог корреляции 0,1 вместо обнуления:
`np.clip(C, 0.1, None) ** 3`. Даёт ровно +0,0005 на всех трёх зёрнах без
исключений. Смысл: при обнулении поле, у которого все соседи слабо коррелированы,
остаётся вообще без поправки; мягкий порог оставляет ему обычное среднее как
запасной путь. Сама по себе величина ниже порога значимости, но знак и величина
одинаковы на всех наборах, а стоит приём одного символа.

Ключ `e02s_best` оставлен без изменений, чтобы опубликованные выше числа остались
воспроизводимыми; правка живёт в отдельном ключе `e02s_best_f10`.

## E08. Сборка финальной конфигурации

**Гипотеза.** E02b и E04 приняты по отдельности и мерились каждый в своём стеке.
Бьют они в разные места: очистка снимает шум наблюдения на всех точках, якорь
правит форму кривой на длинных разрывах, где интерполяция физически не может знать
про сезонный подъём. Значит приросты должны складываться. Но E02 и E06 в своё время
пересеклись, так что складывать без проверки нельзя.

**Что изменили.** Собрано через реестр, а не через наследование: оба метода
приходят из чужих модулей, и склеивать их внутренности значило бы завязаться на
детали, которые авторы вправе поменять. Берутся только предсказания:

```
прогноз = очистка E02b везде
```

Контроль с выключенным якорем совпадает с очисткой E02b до последнего знака на

**Устойчивость.** Приросты складываются, хотя и не полностью: −0,0009, −0,0001 и

```
на разрывах от 45 дней дополнительно:
    0,5 · очистка + 0,5 · климатологический якорь на норме по дню года
```

обучения**. В качестве финальной конфигурации проекта позже заменена бустингом E05,
который использует `final` как один из входных признаков и обгоняет его на всех трёх
зёрнах. `final` остаётся опорным методом и запасным путём: он не требует обучения,
считается за полторы секунды и не зависит от сохранённой модели.

## E09. Слой автоматического сбора данных: какие источники живые

**Гипотеза.** Сервис обязан работать по произвольному полю на карте, а не только по
выданному набору. Значит нужны открытые источники, которые по одному GeoJSON-контуру
за приемлемое время отдают снимки, погоду и границы угодий — без ручной выгрузки
датасета и, желательно, без ключей. Заказчик кейса назвал Copernicus Data Space
(ЕКА) и Google Earth Engine, поэтому они проверялись первыми.

**Что изменили.** Собран слой `src/providers/`:

```
parcels.py    поиск сельхозконтуров в рамке карты (Overpass / OpenStreetMap)
satellite.py  STAC-поиск сцен -> чтение окна COG -> маска облаков -> медиана по контуру
weather.py    суточная температура и осадки (Open-Meteo Archive, реанализ ERA5)
cache.py      файловый кэш ответов, один файл на один ответ
collect.py    склейка всего перечисленного в SeriesInput доменного ядра
```

**Замер источников.** Каталоги проверены руками, в поле `note` каждого источника
записаны наблюдённые коды ответов, а не предположения.

| Источник | Отклик каталога | Вердикт |
| --- | ---: | --- |
| Microsoft Planetary Computer | 0,8 с | **ПРИНЯТ основным**: три сенсора, всё в COG, подпись без регистрации |
| Open-Meteo Archive (ERA5-Land) | 0,5 с | **ПРИНЯТ**: реанализ с 1940 года, без ключа |
| Overpass (OpenStreetMap) | 0,5 с | **ПРИНЯТ**: тот же запрос работает в любой стране |
| Copernicus Data Space (ЕКА) | 0,7 с | **ОТКЛОНЁН** как основной путь |
| AWS Element84 Earth Search | 1,3 с | **ПРИНЯТ запасным**: Sentinel-2 без ключей |

**Почему отклонён Copernicus.** Каталог ЕКА открыт и отвечает за 0,7 с, но пиксели
закрыты сразу тремя способами: основной href — `s3://eodata/...` с
`"auth:refs": ["s3"]`, и GDAL без ключа объектного хранилища отвечает
`InvalidCredentials`; `alternate.https` на `zipper.dataspace.copernicus.eu` помечен
`"auth:refs": ["oidc"]` и без токена отдаёт `401 DAT-ZIP-604 «Token not found»`;
OData-ссылка `Products(...)/$value` — тот же 401. Регистрация через OIDC вопрос
решает, но требует учётной записи, которую нельзя положить в репозиторий, а значит
нельзя и воспроизвести. Вторая причина, независимая от первой: данные там лежат в
SAFE/JPEG2000, а не в COG, и чтение окна даже с ключом будет дороже, чем у двух
других каталогов. Landsat в CDSE только Level-1 — сырые DN без атмосферной
коррекции, к Level-2 несопоставим. Источник оставлен в коде, но включается только
переменными `CDSE_S3_ACCESS_KEY`/`CDSE_S3_SECRET_KEY` либо
`CDSE_USERNAME`/`CDSE_PASSWORD`; без них честно сообщает «требует ключа» и уступает
очередь следующему каталогу.

**Почему отклонён Google Earth Engine.** Отклонён без замера скорости: он требует
собственного проекта в Google Cloud и аутентификации под аккаунтом владельца. Ключ
в репозиторий не положишь, посторонний человек решение не запустит — это нарушение
воспроизводимости, а не вопрос удобства.

**Замер на живом поле под Ростовом, 6 сезонов.**

| Что собрано | Значение |
| --- | ---: |
| Наблюдений NDVI | 453 |
| в том числе Sentinel-2 | 195 |
| в том числе MODIS | 164 |
| в том числе Landsat | 94 |
| Суток погоды | 1 979 |
| Контуров в рамке (Overpass) | 80 полей, 5 695 га |

Ускорение кэша здесь не оптимизация, а часть поведения продукта: повторный показ

осмысленности: ошибка в масштабировании отражения или в маске облаков сломала бы
именно форму кривой.

снимки, погоду и контуры по любому полю мира, существует и работает за приемлемое
время. Просьба заказчика про ЕКА выполнена в той части, в какой она выполнима без
учётной записи: каталог подключён, проверен и задокументирован, но основным путём
сделан Planetary Computer, потому что он отдаёт пиксели.

**ПРИНЯТО.** `pc` основным, `element84` запасным, `cdse` по ключу.

## E10. Прогноз развития поля до конца сезона

**Гипотеза.** Форму сезонной кривой уже знает климатическая норма поля. Значит
вперёд надо переносить не сам индекс, а **отклонение** от нормы, и переносить его
затухающим:

```
ndvi(t0 + k) = норма(t0 + k) + d0 · exp(-k / TAU)
```

Поле, просевшее сегодня, просевшим и останется завтра, но к концу горизонта разница
либо отыграется, либо размоется, и лучшей догадкой снова становится норма.

**Что изменили.** Модуль `src/core/forecast.py`, встроен в `analyze()`, результат
уходит в `meta["forecast"]`.

**Проверка гипотезы до всякой метрики.** Для каждого среза бралось стартовое
отклонение d0, и фактическое отклонение через k дней регрессировалось на него.
Коэффициент — доля отклонения, дожившая до дня k:

| дни вперёд | 1–7 | 8–14 | 15–21 | 22–30 | 31–45 | 46–60 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| доля дожила | 0,77 | 0,66 | 0,50 | 0,31 | 0,06 | −0,05 |

Это и есть экспонента с характерным временем около трёх недель. Крайние значения
важнее середины: после сорока дней текущее состояние поля не несёт о будущем
никакой информации — коэффициент садится на ноль и уходит в минус.

**Подбор времени затухания перебором,** общая RMSE на горизонте 1–60 дней:

| TAU, дней | 10 | 15 | **20** | 25 | 30 | 40 | 60 | ∞ |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| RMSE | 0,1318 | 0,1292 | **0,1287** | 0,1295 | 0,1311 | 0,1351 | 0,1434 | 0,2211 |

Минимум пологий, приходится на 18–22, взято 20. Существенно, что **оптимум лежит
внутри сетки, а не на её границе**: крайние точки перебора — это ровно два наивных
варианта, TAU → 0 даёт «просто норму», TAU → ∞ даёт «останется как сейчас». Модель
честно лежит между ними, и данные говорят, что она там и должна лежать.

**Ретроспективная проверка: 2 010 срезов, 34 925 пар «прогноз — факт».** Срез — это
поле, сезон и дата обрезки из 140/170/200/230-го дня года; история подаётся с
прошлого сезона, ровно в том виде, в каком её собирает `analyze()`. Сравнение идёт
с **фактическими наблюдениями** после среза, а не с восстановленным рядом.
Прогоняется сама `forecast_season`, а не отдельный прототип.

| Горизонт | Прогноз | «Останется как сейчас» | «Просто норма» |
| --- | ---: | ---: | ---: |
| до 7 дней | **0,0947** | 0,1140 | 0,1488 |
| 8–14 дней | **0,0992** | 0,1359 | 0,1384 |
| 15–30 дней | **0,1229** | 0,1911 | 0,1378 |
| 31–60 дней | 0,1250 | 0,2670 | **0,1241** |

Прогноз обгоняет оба наивных варианта на всех горизонтах до 30 дней: минус 17 % к
«останется как сейчас» на первой неделе, минус 36 % к нему же на 15–30 днях, минус
36 % к норме на первой неделе. На 31–60 днях он сравнивается с нормой (0,1250
против 0,1241) — ровно потому, что к этому сроку в неё и превращается. **Хуже
наивных вариантов он не бывает нигде, ни на одном горизонте.**

**Интервал неопределённости.** Заявлен 80-процентный, измеренное покрытие
**0,803** на том же прогоне — это доля фактических наблюдений, попавших между
нижней и верхней границей. Множитель полуширины взят из замера (1,10), а не из
нормальной таблицы (1,282): остатки тяжелохвостые, и теоретический квантиль дал бы
слишком широкий интервал. Ширина растёт как корень из горизонта и перестаёт расти
после 25 дней — без насыщения покрытие уезжает с 0,803 до 0,827, то есть интервал
перестаёт быть 80-процентным.

**Классы риска проверены на факте.** Класс ставится по среднему за горизонт
прогнозному отклонению от нормы; сверка — с фактическим средним отклонением за тот
же горизонт:

| Класс риска | Медиана фактического отклонения |
| --- | ---: |
| low | **+4,7 %** |
| moderate | **−15,0 %** |
| high | **−31,0 %** |

Классы разделяются по факту, а не только по прогнозу, и прогнозное отклонение
оказалось практически несмещённым: медиана факта попадает в тот же бин, из которого
пришёл прогноз.

**Вывод.** Гипотеза подтверждена в границах 30 дней. Дальше прогноз честно
вырождается в климатическую норму, и это свойство данных, а не дефект модели: после
сорока дней память отклонения равна нулю. Продавать такой прогноз как
«предсказание поля на два месяца» нельзя.

**ПРИНЯТО** с тремя границами, вынесенными в отчёт отдельно: горизонт полезного
знания около 30 дней; погода в прогноз не входит вообще; связь с урожайностью в
центнерах не проверялась — прогноз говорит «минус 30 процентов вегетации к норме»,
а не «минус 30 процентов в бункере».

## E11. Оценка поля как объекта риска

Самый содержательный отрицательный результат за сутки: гипотеза не подтвердилась, и
разбор причины оказался важнее самого балла.

**Гипотеза.** Балл риска, собранный из частоты и глубины провалов поля, должен
согласоваться с разметкой `status`: поле, у которого много строк «Угнетение
биомассы» и «Критическая аномалия», должно получать низкий балл.

**Что изменили.** Модуль `src/core/scoring.py`: балл 0…100, буква A…E и разбор по
сезонам. Четыре компоненты — устойчивость, стрессовая нагрузка, продуктивность и
тренд; прокси урожайности — интеграл NDVI за вегетационный сезон.

**Гипотеза опровергнута. Связи балла с разметкой нет: Spearman +0,10 при p = 0,54.**
Знак к тому же «неправильный» — балл слегка растёт вместе с долей проблемных строк.

**Разбор причины — три замера подряд.**

1. **Доля строк ниже −1σ одинакова у всех полей.** По 39 полигонам обучающего
   набора она равна **0,159 ± 0,028** при теоретическом P(z < −1) = **0,1587**.
   Совпадение с теорией до третьего знака при разбросе в одну шестую от величины
   означает, что величина полем почти не управляется. Причина механическая:
   `z = (ndvi − норма) / std`, и `std` считается **по истории того же поля**. Порог
   нормируется на собственную изменчивость поля, поэтому доля его превышений
   определяется формой распределения, а не качеством поля.
2. **Эта доля не предсказывает даже сама себя во времени.** Доля проблемных строк
   поля в 2010–2019 против его же доли в 2020–2024: **ρ = −0,147**. То есть в
   величине нет устойчивого свойства поля вообще — подгонять под неё оценку риска
   бессмысленно, она не переносится даже на то же самое поле.
3. **Доля критических строк растёт с устойчивостью: ρ = +0,63.** Это тот же эффект,
   доведённый до предела: у стабильного поля собственная сигма мала, и обычное
   колебание пробивает −2σ легче, чем у разболтанного. Балл устойчивости и частота
   «критических аномалий» связаны **положительно** — значит согласовывать их между
   собой было бы прямой ошибкой, а не улучшением.

**Настоящая проверка — прогнозная, а не по разметке.** Балл считается по сезонам
2010–2019 (ядро видит только их, климатическая норма тоже строится только по ним), а
проверяется по поведению поля в 2020–2024:

| Что предсказываем баллом 2010–2019 | Spearman на 2020–2024 |
| --- | ---: |
| Глубина худшего провала | **+0,46** |
| Межгодовой разброс урожая (сезонного интеграла) | **−0,63** |

Знаки правильные: высокий балл — меньше разброс и мельче худший провал. По
компонентам, тот же протокол:

| Компонента | Разброс 2020–2024 | Глубина худшего | Частота провальных |
| --- | ---: | ---: | ---: |
| stability | −0,71 | +0,54 | −0,28 |
| stress | −0,55 | +0,45 | −0,31 |
| productivity | −0,25 | +0,13 | −0,12 |
| trend | +0,24 | −0,13 | +0,01 |

Отсюда веса: stability 0,35, stress 0,35, productivity 0,20, trend 0,10. Тренд —
единственная компонента, чья польза вне обучающего периода **не** подтвердилась
(связь неотличима от нуля), поэтому у неё минимальный вес; оставлена, потому что
деградирующее поле андеррайтеру показывать надо.

Внутри стрессовой нагрузки веса расставлены тем же замером, и результат тот же:

| Измеритель по 2010–2019 | ρ с разбросом 2020–2024 | ρ с глубиной худшего | Вес |
| --- | ---: | ---: | ---: |
| Частота провальных сезонов | +0,60 | −0,37 | 0,25 |
| Глубина худшего сезона | −0,62 | +0,42 | 0,20 |
| Средний минимум z за сезон | +0,61 | −0,51 | 0,25 |
| Самый длинный период угнетения | +0,26 | −0,23 | 0,20 |
| Число дней с z < −1 за сезон | **−0,03** | −0,17 | **0,10** |

Число дней ниже −1σ — та самая величина, которую прямо требует постановка, — не
предсказывает ничего. Она оставлена в оценке, потому что её требует постановка и
потому что её видит агроном в интерфейсе, но вес у неё вдвое-втрое ниже, чем у
измерителей, которые работают.

**Пойманная по дороге утечка, из-за которой первая версия замера дала обратный
знак.** Климатология организаторов — это leave-**one**-year-out по всем 15 сезонам:
норма 2015 года считается по 2010–2014 и 2016–2024. Значит норма, применённая к
первому десятилетию, уже видела второе, и «прогнозная» проверка на самом деле
подглядывала в будущее. Первая версия замера на этой норме дала связь балла с
разбросом будущего **+0,45** — знак, противоположный правильному. После пересчёта
нормы только по 2010–2019 знак перевернулся на **−0,63**. Это второй случай в
проекте, когда кривой протокол давал **другое ранжирование**, а не просто другую
цифру; первый — геометрия локального контрольного набора (E01, раздел про
исправление протокола).

**ПРИНЯТО с явной оговоркой.** Балл не связан с `status` и связываться не должен —
это доказано числом, а не оставлено на усмотрение. Проверка балла только прогнозная.
Калибровка шкал (узлы кусочно-линейных шкал, границы букв A…E) сделана на 39 полях
одного климатического региона; раскладка на контрольном наборе A 4, B 14, C 8, D 9,
E 4 поля. За пределами региона узлы шкал придётся пересчитывать.

## E12. Журнал агротехнических работ

**Гипотеза.** У сервиса есть версия причины «причина не погодная»: все погодные
пороги проверены, ни один не сработал. На этом объяснение обрывается, и агроному
дальше идти некуда. Если он введёт, что и когда делал на поле, сервис сможет связать
работу с просадкой сам.

**Что изменили.** Модуль `src/core/agrolog.py` и вызов из `analyze()`. Правила
связывания взяты из агрономии, а не подобраны по метрике:

| Правило | Окно | Поправка уверенности |
| --- | --- | ---: |
| Фитотоксичность после гербицида или инсектицида | 3–14 дней после обработки | +0,15 к версии «не погодная», +0,10 к «резкому событию» |
| Уборка внутри периода — падение плановое | пересечение с периодом | +0,25 к версии «уборка» |
| «Резкое событие» оказалось плановой уборкой | пересечение с периодом | −0,35, версия переписывается |
| Обработка почвы объясняет падение | пересечение с периодом | −0,30 |
| Подкормка была, а отклика нет | 7–21 день | +0,05 |
| Полив во время «засухи» опровергает дефицит влаги | 7 дней | −0,25 |

Границы окон — не догадки: системный гербицид проявляется ожогом и торможением
роста на третий–четырнадцатый день, раньше не успевает, позже уже отпустило. Журнал
**не трогает** границы периода и класс серьёзности: они получены из измерения, а
журнал вводит человек, и ошибка в нём не должна переписывать данные. Пустой журнал
или отсутствие работ рядом с периодом дают пустую строку и нулевую поправку —
молчание тоже часть логики.

**Замер.** На AOI-0002 из 22 найденных периодов журнал дополнил **9**. Раскладка
версий причины изменилась так:

| Версия причины | Было | Стало |
| --- | ---: | ---: |
| `harvest` (плановая уборка) | 1 | **3** |
| `non_weather` (причина не погодная) | 8 | **6** |

Два периода, которые сервис не мог объяснить вовсе, получили конкретное
объяснение — плановую уборку.

**Числовой валидации у этого блока нет, и это надо назвать прямо.** Настоящих
журналов полевых работ по полям набора не существует: организаторы их не выдавали, а
разметка `status` — детерминированная функция от z-оценки и про агротехнику не знает
ничего. Замер выше показывает, **что механизм срабатывает и на скольких периодах**,
но не показывает, что он прав. Проверить правила лагов можно было бы только на
хозяйстве с реальным журналом работ и известным исходом — такой проверки в проекте
нет, и выдавать замер «9 из 22» за подтверждение правил нельзя. Журнал в
демонстрации подаётся функцией `example_journal()` — типовым календарём озимой
пшеницы для Ростовской области: сев в конце сентября, подкормка по мёрзлоталой почве
в конце февраля, гербицид в апреле, фунгицид по флаг-листу в мае, уборка на переломе
июня и июля.

**ПРИНЯТО как продуктовая возможность с пометкой «не валидировано числом».** Правила
при этом проверяемы: лаги вынесены в именованные константы, поправки уверенности
ограничены диапазоном 0,05…0,95, а версию причины журнал переписывает ровно в одном
случае — когда в период попала уборка.

## E13. Две починки ядра, найденные на живых данных

Обе ошибки на выданном наборе не проявлялись вовсе и вылезли только тогда, когда
ядро впервые получило ряд, собранный слоем провайдеров по живому полю.

**Починка 1. Нижняя граница разброса нормы: 0,02 → 0,05.**

*Что было не так.* На полях с короткой историей z-оценка доходила до **−25**. На
пашне идёт севооборот: норма, построенная по двум прошлым сезонам, описывает другую
культуру, отклонение выходит до 0,5 NDVI и делится почти на ноль. Продукт при этом
уверенно сообщал «критическая аномалия» там, где просто не хватало истории.

*Обоснование новой границы — физическое, а не подобранное.* Собственный шум одного
наблюдения NDVI измерен и равен **0,066** (std разности значений соседних дней
0,0931, делённая на корень из двух). Норма построена **из тех же наблюдений**,
поэтому её разброс не может быть заметно меньше этого шума: заявить норму втрое
точнее измерения, которым она получена, нельзя. 0,05 — это чуть ниже 0,066, то есть
граница не режет реальные узкие нормы, а отсекает только вырожденные.

**Починка 2. Периоды угнетения ищутся только в вегетационный сезон.**

*Что было не так.* **Сервис объявлял критическую аномалию в январе** — на поле, где
просто лежал снег. Вне сезона низкий индекс это снег, голая почва и растительные
остатки, а не состояние посева; спутниковый слой снег маскирует (класс SCL 11 и бит
5 у Landsat), поэтому зимние значения ряда почти целиком экстраполяция. Организаторы
по этой же причине ограничили свой набор апрелем–октябрём, но их ограничение
действовало на данные, а не на ядро — на живом ряде сетка сплошная, и зима в неё
попадает.

*Как исправлено.* Поиск событий ведётся по `z_for_search`, где значения вне
апреля–октября заменены на NaN. **Сам ряд и z-оценка за зиму остаются в ответе**:
график должен быть непрерывным, скрывается только поиск событий.

**Контроль на эталонной разметке.** Обе правки меняют поведение ядра, поэтому
согласие со `status` перемерено после каждой: **0,9417 на 6 282 точках**, не просело
ни разу. Это ожидаемо и является частью вывода: правки убирают ложные срабатывания
вне сезона и на короткой истории, то есть ровно там, где эталонной разметки нет
вовсе, — и потому на согласии с ней не сказываются.

**ПРИНЯТО.** `MIN_STD = 0,05` в `src/core/climatology.py`,
`SEASON_MONTHS = (4, 10)` в `src/core/analyze.py`.
