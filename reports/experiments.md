# Журнал экспериментов

Каждая запись: гипотеза, что изменили, число до и после, вывод. Из этого журнала
собирается исследовательский отчёт — критерии «Baseline и отправная точка» и
«Эксперименты и сравнения», 10 баллов рубрики.

Все числа в журнале получены одной командой и сопоставимы между собой:

```bash
python -m src.ml.validate
```

## Протокол локальной валидации

Лидерборд отдаёт одну цифру в сутки и годится только для проверки формата файла.
Все решения принимаются по локальному протоколу, и только по нему.

**Как строится контрольный набор.** Наивное «спрятать 20 % случайных известных
значений» не годится: у случайной точки разрыв почти всегда короткий, а в реальном
наборе организаторов встречаются разрывы до 189 дней, и именно на них методы
расходятся сильнее всего. Поэтому применяется маскирование по шаблону:

1. Из тестового файла снимается геометрия всех 3 112 контрольных точек — тройка
   «расстояние до ближайшего известного значения слева, расстояние справа, месяц».
2. Каждая такая тройка становится шаблоном. Чтобы его воспроизвести, берётся
   случайное известное наблюдение нужного месяца, и вместе с ним прячутся все
   наблюдения, попавшие внутрь интервала шаблона. Тогда у спрятанной точки соседи
   оказываются ровно там же, где у настоящей контрольной точки.
3. Размещение отбраковывается, если фактическая длина разрыва попала не в тот бин,
   что у шаблона. Без этой проверки захват соседей растягивает разрывы, локальный
   набор становится заметно тяжелее реального, и выводы смещаются: в первой версии
   протокола доля разрывов 14–29 дней вышла 37,6 % против реальных 15,9 %.
4. По бинам длины разрыва держится квота. Без неё короткие шаблоны, которым труднее
   найти место, недобираются, длинные добираются легко, и перекос возвращается.
5. У спрятанных строк стираются **все** признаки, кроме `anon_polygon_id`, `date` и
   `crop_type` — ровно так замаскированы настоящие контрольные точки. Иначе
   валидация мерила бы задачу легче реальной.
6. Оценивается только центр шаблона. Соседи, снесённые заодно, из обучения выбывают,
   но в метрику не идут — иначе набор перекосило бы в сторону коротких разрывов.
7. Центром шаблона может быть только строка тестового файла: именно такие строки
   мы предсказываем на самом деле.

**Результат — совпадение геометрии по всем бинам:**

| разрыв, дней | контрольные точки, % | локальная валидация, % |
| --- | --- | --- |
| 1–2 | 6,6 | 6,5 |
| 3–4 | 17,7 | 17,8 |
| 5–7 | 27,3 | 27,4 |
| 8–13 | 27,5 | 27,6 |
| 14–29 | 15,8 | 15,6 |
| 30–61 | 1,4 | 1,4 |
| 62–181 | 3,2 | 3,2 |
| 182+ | 0,4 | 0,4 |

**Разбиение.** GroupKFold по `anon_polygon_id`, 5 фолдов: поле целиком либо в
обучении, либо в контроле. Иначе бустинг подглядит соседние дни того же поля и
локальная цифра разойдётся с лидербордом.

**Объём.** 2 999 оцениваемых точек, 8 094 скрытых строки (16,8 % известных
значений), 78 полигонов, зерно 42. Протокол детерминирован.

**Метрика.** `RMSE` по спрятанным точкам и `GapScore = round(30 · max(0, 1 − RMSE / 0.10), 2)`.

**Что исключено сознательно.** Шаблоны с односторонним разрывом (край ряда)
отброшены: воспроизвести их, не разрушив полигон целиком, нельзя. В реальном
наборе таких точек меньше процента.

## E00. Разведка данных

**Что делали.** Разбор `private_features.csv`, затем — после появления —
`train_dataset.csv`. Подробности во втором файле: `reports/eda_train.md`.

**Наблюдения по тестовому набору.**

1. `primary_ndvi` — склейка трёх сенсоров по приоритету. Там, где доступен
   Sentinel-2, значение совпадает с `s2_ndvi` до последнего знака: проверено на
   7 815 строках, доля точных совпадений 1,000. Иначе Landsat, иначе MODIS.
2. В контрольных строках замаскированы все признаки, кроме `anon_polygon_id`,
   `date` и `crop_type`. Даже `doy`, `year`, погода и климатология.
3. Разрывы короткие: медиана расстояния до ближайшего известного значения — 3 дня
   с каждой стороны, 75-й процентиль 6 дней, максимум 189. У 99,2 % контрольных
   точек соседи есть с обеих сторон, экстраполяция почти не нужна.
4. История неравномерна: 19 полигонов покрывают 2010–2025, остальные 59 — только
   сезон 2025. Климатическая норма по собственной истории доступна не всем.

**Наблюдения по обучающему набору (99 955 строк, 39 полигонов).**

5. **Сплит между файлами идёт по годам, а не по датам.** Пересечение пар
   «полигон + дата» ровно нулевое, и пересечение пар «полигон + год» тоже ровно
   нулевое: для всех 39 полигонов train — это сезоны 2010–2024, а test — только
   сезон 2025. Ближайшее наблюдение train к контрольной точке отстоит минимум на
   153 дня. Отсюда прямое следствие, проверенное числом в E01b.
6. **Формула климатологии восстановлена точно.** `ndvi_climatology_mean` — это
   среднее `primary_ndvi` того же полигона по всем годам **кроме текущего**, в окне
   ±8 дней по дню года. MAE воспроизведения 0,00163; окна ±7 и ±9 дают 0,006 и
   0,005, то есть ширина определена однозначно. `n_reference_years = 15` при 16
   годах истории — это leave-one-out. Следствие: замаскированную у контрольных
   точек климатологию можно пересчитать самостоятельно и получить её для 2 884 из
   3 112 точек (92,7 %).
7. **`ndvi_zscore` = (primary_ndvi − clim_mean) / clim_std**, 30 520 из 30 520
   точных совпадений, максимальное расхождение 3,2·10⁻¹⁴. Сглаживания нет.
8. **Разметка `status` воспроизводится порогами из `src/contracts.py` идеально:**
   z ≥ −1 «Штатное развитие», −2 ≤ z < −1 «Угнетение биомассы», z < −2
   «Критическая аномалия». Совпадение 1,000000, ошибок 0 из 30 520.
9. **Собственный шум наблюдения 0,066.** std разности значений при шаге ровно один
   день равен 0,0931, отсюда шум одного наблюдения 0,0931/√2.
10. **Одиночные выбросы измерены:** 5,60 % троек подряд идущих наблюдений, где
    средняя точка отклоняется от полусуммы соседей больше чем на 0,10 при
    расхождении самих соседей меньше 0,05. При пороге 0,15 — 3,15 %. Значений вне
    диапазона [0, 1] в train 38, все отрицательные.
11. **Погода частично восстановима.** `era5_temp_c` принимает 9–12 уникальных
    значений на дату при 78 полигонах: поля сбиваются в 37 погодных групп с общей
    метеосводкой. 782 контрольные точки (25,1 %) получают точную погоду от
    полигона-собрата из той же группы на ту же дату.
12. **Норма по типу культуры как предиктор слаба.** Медиана корреляции кривых
    внутри культуры 0,949 против 0,855 между культурами; RMSE между двумя полями
    озимой пшеницы 0,108 — хуже текущей ошибки восстановления.

**Вывод.** Основной источник ошибки — не разрывы, а шум наблюдения: 0,066 против
рабочих 0,080 RMSE. Значит рычаг не в точности интерполяции между двумя точками, а
в подавлении шума по окну, и запас до физического потолка невелик.

не подтвердился, см. E03. Оставляю запись как есть: это показательный пример того,
почему разрез по бинам нельзя читать без проверки на других зёрнах.

**Принято в работу.** Уиттекер λ = 1000 как новая точка отсчёта вместо смеси 50/50.

## E01b. Сколько даёт подмешивание train_dataset в ряд

| Ряд только из тестового файла | 0,0796 | 6,12 |

## E02. Робастная очистка ряда

**Гипотеза.** Собственный шум наблюдения 0,066 — основной источник ошибки. Кроме
грубого брака (значения вне [0, 1]) есть одиночные провалы от облачности: сенсор
занижает NDVI на одну дату, соседние даты нормальные. Сглаживание такой провал
размазывает по окрестности вместо того, чтобы его выкинуть. Медианный фильтр по
трём точкам перед сглаживанием должен дать выигрыш.

**Что изменили.** Проверено 47 вариантов конвейера «очистка → сглаживание».

| Компонент, накопительно | RMSE | Дельта |
| --- | --- | --- |
| Контроль (Уиттекер λ = 1000) | 0,0799 | — |
| Веса наблюдений по сенсору 1 / 0,8 / 0,5, λ = 800 | 0,0786 | −0,0013 |
| + придавливание брака к границе вместо выбрасывания | 0,0781 | −0,0018 |
| + мягкая медиана по трём точкам, порог 0,20 | 0,0777 | −0,0022 |
| + окно медианы по календарю ±8 дней вместо трёх подряд идущих наблюдений | **0,0765** | **−0,0034** |

**Три находки, которые стоят отдельного упоминания.**

1. **Гипотеза про асимметрию опровергнута.** Считалось, что облачность занижает
   NDVI, но почти никогда не завышает. На данных наоборот: одиночных всплесков
   вверх больше, чем провалов вниз — 41–44 % вниз на всех порогах, и на train, и
   на test. Зеркальный фильтр «сбивать только всплески вверх» (0,0795) обгоняет
   фильтр «сбивать только провалы вниз» (0,0801). Асимметрия есть только в дальнем
   хвосте и в грубом браке.
2. **Выбрасывать бракованную точку хуже, чем оставить.** Придавливание к границе
   даёт −0,0005, и весь эффект сидит в бине 62–181 дня (0,1341 → 0,1215). Это края
   сезона, где выброшенная точка была единственной опорой перед зимним перерывом.
3. **Календарное окно решает больше, чем сам фильтр.** По отдельности мягкая
   медиана давала −0,0008, календарный режим не давал ничего, а в сборке разница
   между режимами составила 0,0012 — больше, чем каждый компонент поодиночке.

**Веса по сенсору прошли два контроля,** и это важно, потому что эффект от них
самый крупный. Первый: подбор λ без весов ничего не даёт (λ = 1250 → 0,0799,
λ = 2000 → 0,0803), то есть выигрыш не сводится к смещению силы сглаживания.
Второй: те же веса, розданные наблюдениям случайно, дают 0,0804 — хуже контроля.
Измеренный шум: Sentinel-2 0,0394, Landsat 0,0536.

**Честная оговорка про величину.** Окно и порог подбирались на зерне 42. Порядок
методов на других зёрнах сохраняется и лучший вариант ни разу не проигрывает, но
выигрыш меньше: −0,0034 на зерне 42, −0,0014 на 7, −0,0009 на 2024. Реалистичная
оценка эффекта — **около двух тысячных**, а не три с половиной.

**Принято в работу.** Конвейер `e02_wsoft_clamp_s20t`. Пересечение с E06 меряется
отдельно — оба метода сильнее всего играют на длинных разрывах, складывать их
эффекты нельзя.

## E03. Сила сглаживания под длину разрыва

**Гипотеза.** Единая λ на весь ряд — компромисс. На коротком разрыве сглаживание
должно быть слабее, чтобы не срезать реальную динамику; на длинном сильнее.

**Что изменили.** Сетка единой λ от 300 до 50 000 на трёх зёрнах; `order = 3`
вместо 2; побинный подбор λ и доли примеси линейной интерполяции.

| Проверка | λ = 1000 | Побинный подбор | Дельта |
| --- | --- | --- | --- |
| Конфигурация подобрана на зерне 42, проверка на зерне 42 | 0,0799 | 0,0793 | +0,0006 |
| Та же конфигурация, проверка на зерне 7 | 0,0854 | 0,0856 | −0,0001 |
| Та же конфигурация, проверка на зерне 2026 | 0,0808 | 0,0809 | −0,0001 |

**Вывод. Гипотеза не подтвердилась.** Выигрыш держится только на том наборе, на
котором подбирался, и не переносится. Сам выбор λ пляшет от зерна: для бина
62–181 дня оптимум оказывается λ = 50 000 при доле линейной 0,8 на зерне 42,
λ = 2000 при доле 0,4 на зерне 7 и λ = 3000 при чистом Уиттекере на зерне 2026.
Причина простая — объём: в бинах 30–61 и 62–181 всего 43 и 96 точек.

Побочные результаты, которые закрывают вопросы окончательно:

- Оптимум единой λ = 1000 подтверждён на трёх зёрнах и он внутренний, не на
  границе сетки; дно пологое, λ от 700 до 1500 различаются на 0,0002.
- `order = 3` равномерно хуже на 0,0002–0,0004 по всей сетке и на всех зёрнах.
- Примесь линейной интерполяции при правильной λ не нужна вовсе. Смесь 50/50 из
  E01 выигрывала только потому, что компенсировала недосглаживание при λ = 100.

**ОТКЛОНЕНО: прирост в пределах шума.** Методы оставлены в реестре как
воспроизводимое подтверждение замера, в финальную конфигурацию не идут.

## E06. Суточная поправка по соседним полям

Эксперимента не было в исходном плане. Он дал самый крупный прирост в проекте.

**Гипотеза.** Считалось, что 0,066 собственного шума наблюдения — неустранимый
потолок, потому что шум независим. Это неверно. Значительная его часть общая для
полей, снятых одним пролётом: дымка, тонкое облако, угол Солнца, поправки
атмосферной коррекции сдвигают NDVI сразу у группы полигонов в одну сторону. А
наблюдения соседних полей на дату контрольной точки **не замаскированы** —
организаторы прячут только целевой полигон.

**Проверка гипотезы до написания метода.**

| Величина | Значение |
| --- | --- |
| Стандартное отклонение остатка от сглаженного ряда | 0,0643 |
| Медиана парной корреляции остатков, все пары полигонов | 0,246 |
| Медиана корреляции остатка поля со средним остатком его погодной группы | 0,521 |

Погодные группы определяются по `era5_temp_c`: она принимает 9–12 уникальных
значений на дату при 78 полигонах, то есть поля сбиваются примерно в 37 групп с
общей метеосводкой. Корреляция 0,52 означает, что около четверти дисперсии
«шума» объяснимо и его можно вычесть.

**Что изменили.** Две версии.

Простая — восстановить ряд как обычно, затем прибавить долю от агрегата остатков
соседей на дату цели. Усиленная — та же суточная помеха сидит и в опорных
наблюдениях самого поля, значит её надо сначала вычесть из всего ряда,
пересгладить очищенные значения, и только потом вернуть на дате цели:

```
c(t)  — общая суточная поправка, усечённое среднее остатков по всем полям
y'(d) = y(d) − c(d)                     очищенные наблюдения
прогноз = сглаженный y'(t) + beta · c(t)
```

Поправка для каждого поля считается **без него самого** (leave-one-out), иначе
поле частично вычитало бы собственный шум и оценка была бы смещённой.

**Устойчивость.** Оптимум по доле переноса пологий: 0,9 и 1,0 дают 0,0735, 1,2
даёт 0,0738 — это не остриё. Проверка на другом зерне: база 0,0854, метод 0,0769,
прирост 0,0085 против 0,0087 на зерне 42. λ = 1000 выигрывает на обоих зёрнах
(λ = 300 → 0,0731, λ = 3000 → 0,0729 при зерне 42).

**Величина эффекта.** Стандартное отклонение самой суточной поправки 0,0339 при
разбросе остатка 0,0643, поправка применяется на 95 % дней. То есть из шума
наблюдения снимается около половины по амплитуде.

**Вывод.** Утверждение «ниже RMSE 0,075 не опустится никто» опирается на
предположение, что шум наблюдения независим между полями. Предположение неверное.
Физический потолок надо пересчитывать по остаточному шуму после снятия общей
составляющей: 0,0643 → около 0,055.
